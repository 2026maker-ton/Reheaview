# 보고서 역량 연결·공급자 표시 정정 (2026-11-05)

범위: PROJECT §2.6·§4.4·§7.7, P4·P5·P1-9. 지원서 주장 검증 → 근거 기반 코칭의 보고서 정합성 수정이며 평가 정책 변경이 아니다.

## 결함과 수정

- 질문에 배정된 `competency_ids`는 보고서 역량 차트에 전달됐지만 `buildAxes`의 인재상 적합성 입력에서 누락됐다. 이제 같은 ID를 전달한다. 답변에 역량 이름을 반복하지 않아도 승인된 질문 연결로 집계하며, 무관한 ID·연결 없는 답변은 미관찰로 유지한다. 중복 연결은 같은 답변을 여러 번 세지 않는다. 기존 답변 점수나 근거를 지어내지 않는다.
- `answer.review`가 Claude로 실행돼도 보고서 점수 라벨과 코멘트 근거가 Gemini로 고정됐다. 이제 해당 재검토 호출의 trace 공급자로 표시한다. 보고서 전체 평가기와 질문별 검토 공급자가 달라도 각각의 실제 출처를 유지한다. 비필수 모드의 실패·차단은 규칙 표시, strict 실패는 기존 실패·재분석 경로를 유지한다.
- 결과 도움말의 단어 일치 전용 설명·Gemini 고정 설명·항상 규칙 폴백한다는 설명을 현재 동작에 맞췄다. PROJECT §2.6·§4.4에 현재 라우팅과 과거 고정 배치의 우선순위를 명시했다. 과거 문서·결정 기록은 당시 이력으로 유지한다.

## 검증과 한계

가짜 키·주입 공급자 스텁으로 Claude/Gemini 표시, 실패 시 규칙 표시, 질문 역량 연결, 잘못된 ID·미관찰·중복 집계를 회귀 시험한다. 브라우저 검사는 Mock 모드다. 실제 외부 AI 요청은 0회이며 사람 평가 타당성·실배포 적용은 검증 범위 밖이다. 기존 성공 보고서는 자동으로 다시 만들지 않으며 수정은 새로 생성되는 보고서에 적용된다. 기존 §7.5의 역사 문서·비용 모델 불일치와 미관찰 1 정책의 한계는 남는다.
