# 게스트 버튼 숨김과 음성 답변 자동 완료 복구

> 이력: 이 문서의 발화 후 30초 기준은 최신 사용자 요청으로 3초로 변경됐다. 최초 무발화 30초는 유지한다. 현재 동작은 PROJECT.md §7.7과 `2026-11-01-speech-endpoint-family-filter.md`를 따른다. 당시 검증 수치는 그대로 보존한다.

사용자 요청: 게스트의 내 데이터·로그아웃 버튼 제거, 말을 마친 뒤 다음 질문으로 넘어가지 않는 현상 점검. PROJECT.md §2.5·§6.1·§7.7, P3 음성 면접·P5 게스트 UX에 해당한다. 지원서 주장 → 답변 → 근거 기반 코칭의 답변 수집 경로를 복구한다.

## 원인과 수정

- 음성 게이트는 한 번 `spoke=true`가 되면 현재 소리의 주기성과 관계없이 RMS가 큰 소음을 발화로 반환했다. 발화 뒤 비주기적 소음을 넣은 단위 테스트에서 이를 재현했다. 현재 프레임의 주기성을 사용하도록 수정하되 과거에 말했는지 나타내는 `spoke`는 보존한다. 연속 정적 30초·전체 답변 60초 기준은 유지한다.
- 녹음 종료 이벤트가 도착하기 전에 60초 제한이 겹치면 종료 중이라는 상태를 알지 못하고 다시 종료하거나 마지막 음성을 잃을 수 있었다. processing 상태를 종료 요청 전에 표시하고, 동시에 요청한 stop은 같은 최종 오디오를 기다린다. 중단된 capture의 후속 프레임은 무시한다.
- 브라우저 전사 fetch에는 자체 시간 제한이 없어 네트워크 무응답 시 자동 진행이 계속 대기할 수 있었다. JSON 본문 수신까지 포함해 35초 후 취소한다. 빈 녹음·전사 실패는 텍스트 확인으로 복구하고, 이전 질문/이전 면접의 늦은 응답은 새 질문에 반영하지 않는다. 이 복구 상태에서는 사용자 확인·제출이 필요하다.
- 게스트 상태에서 내 데이터·로그아웃 버튼을 숨긴다. 회원 계정에서는 표시하고, 기존 삭제·소유권 API와 공급자 보호 게이트는 유지한다.

## 검증 범위

브라우저에 가상 마이크·MediaRecorder·가상 시계를 넣고 전사/명령/보고서를 Mock한다. 발화 후 29초 배경 소음에서 미제출 → 30초 후 전사 1회·제출 1회 → 다음 질문 → 무발화 질문 자동 제출 → 마지막 결과 화면 도착을 확인한다. STT 무응답과 60초 경계에서는 전사가 중복되지 않고 오류 안내·텍스트 입력으로 전환되는지 확인한다. 실제 마이크나 사용자 음성을 외부로 보내지 않으며, 실모델을 추가 호출하지 않는다. 게스트의 실제 외부 STT는 기존처럼 차단된다.

변경 파일: `public/screens/login.js`, `public/screens/room.js`, `public/core/vad.js`, `public/core/speech-gate.js`, `tests/domain/speech-gate.test.mjs`, `tests/domain/vad-wait.test.mjs`, `tools/e2e-ui.mjs`, `tools/e2e-room-cases.mjs`, `PROJECT.md`, 이 문서. 과거 3초 정적·무조건 발화 판정 설명은 현재 정책을 대체하지 않는다. 실기기 잡음 환경·마이크 설정·한국어 STT 정확도는 별도 검증이 필요하다.

최종 결과: `npm run check:project` 4/4 통과, `npm test` 366 통과·0 실패, Chromium E2E 125개 체크 통과·0 실패. 브라우저 검사는 Mock·합성 음성으로 수행했으며 실마이크·실모델·배포 검증은 하지 않았다. 이 변경의 실제 AI 호출 수는 0회다.
